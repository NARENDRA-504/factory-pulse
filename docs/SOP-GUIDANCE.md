# SOP guidance on every module

The signed-in application shell displays `SopGuidancePanel` above every module. A short next step stays visible; View steps expands role and module instructions. Navigation updates the instructions. The panel supports mobile layout, loading, explicit unavailability and Retry. It performs no operational writes or external AI requests.

`GET /api/v1/guidance/sop?module=machines&machine_id=MCH-001&question=temperature` uses the existing server authentication dependency and checks both the module and machine against the server-derived role. It returns module guidance from `knowledge/assistant/sop.md` and a role-filtered procedure from `knowledge/sop/catalog.json`, with source, revision, approval status and bounded authorized evidence. It returns no personnel records. A machine status shared by a full sensor round does not identify a faulty sensor, so default procedure retrieval is general; selecting a topic retrieves its specific procedure.

These are general training procedures, pending site approval. They do not infer live machine conditions, provide equipment-specific isolation/repair/restart instructions, or certify configured thresholds as safety limits. Replace the training content only after approved procedures are provided and reviewed; retain clear approval and revision information.

Activation requires restarting the FactoryPulse backend after the new route is installed. Existing frontend development sessions reload the changes; a deployed frontend needs a rebuild. No schema migration or Simulator change is needed.

Route tests verify dependency wiring and direct handler authorization, not a live HTTP/database session. TypeScript and production build pass. Existing Vite config and bundle-size warnings remain. Screenshots are in `.local/sop-rag-desktop.png` and `.local/sop-rag-mobile.png`. The earlier network-preview failure was avoided by bundling the preview into an isolated page.

SOP questions in the chatbot retrieve stored role steps directly, with citations, and bypass Gemini rewriting. General factory questions retain existing optional Gemini behavior. No ML model, new alert delivery, automatic incident creation or machine control was activated by this change. See `knowledge/sop/README.md` for the approval and catalog process. The training documents contain conditional safe-stop/escalation/handover guidance; exact emergency-stop, isolation and restart instructions require reviewed equipment-specific source material.
